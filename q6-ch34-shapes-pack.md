# Q6 — ch. 3/4 shape replay pack

Implementation unit Q6 of the replay-first rollout
([`replay-first-rollout.md`](replay-first-rollout.md) → *Wave 3*). This is the
fifth chapter pack (after ch. 8 defense, ch. 7 riichi/dama, ch. 5 value and
ch. 9 seating/calls): the **ch. 3 tile-efficiency shape** family plus the
**ch. 4 ryanmen** rule, mined from the same 1,542-game AI self-play corpus and
classifier v3. No new classifier was needed; every shipped lesson was already
recognised.

**Shipped artifact:** `frontend/public/scenarios/`, pack
`replay.ch34-shapes.2026-11`, **822 reviewed bases, 0 variants, 724,376 bytes**,
six lessons across ch3.2/ch3.3/ch4.1. All six clear the 40-base coverage floor,
so all six become **replay-default**. The four thin ch3.2/ch3.3 lessons
(`perfect_one_away` 25, `pair_count_open` 21, `nobetan_keep` 3,
`ryankan_break` 1 measured stable labels) are **not shipped**; they stay
generated by default until corpus growth `C9`.

The four below-floor lessons are kept **out of the selection scope** this time,
rather than selected-and-dropped as Q5 did: the task's measured supply already
shows none of them can clear 40 (25/21/3/1 stable labels), so spending queue
slots on them would only add review noise. They keep their generated default,
and the content check's lesson set names only the six shipped ids, so a stray
ch3/ch4 thin lesson cannot leak into the pack.

The 868 → 822 difference is assembly's actor-hand dedupe (46 bases with a
duplicate 13/14-tile hand string), not a lesson floor: every shipped lesson
stayed far above 40.

## Pipeline

```bash
export RIICHI_DATA_DIR="$HOME/riichiprac-data/q2-ch8-defense-2026-11"
BIN=target/release/mine_replays
cargo build --release --features miner --bin mine_replays

# 1. Labels are classifier v3 from B4 (the one label pass already ran); this
#    pack reuses them, so it does not re-evaluate Mortal. Weights: AGENTS.md
#    §5c (not needed for a stable-book selection or a book-only transform).

# 2. Select the six shipped lessons across three book sections. The thin
#    lessons are deliberately absent from both --section/--lesson scopes.
$BIN --data-dir "$RIICHI_DATA_DIR" select \
  --pack-id replay.ch34-shapes.2026-11 \
  --size 3000 --held-out-share 0.03 --seed q6-ch34-2026-11 \
  --section ch3,ch4 \
  --lesson protorun_priority,pair_count,skipping_block,protorun_plus_one,nakabukure_ready,ryanmen_protorun \
  --stable-book-only \
  --corpus-family mortal_mirror,mortal_sampling_sweep,akochan_tactics,akochan_vs_mortal,heterogeneous_table \
  --max-per-replay 2 --extracted-only --workers 0 --progress \
  --max-section-share 0.60 --max-kind-share 0.95 --max-turn-share 0.95 \
  --json > testdata/reports/q6-ch34/selection-report.json

# 3. Mechanical review with the new combined ch34 scope (prefix list over
#    ch3.2/ch3.3/ch4.1, lesson-scoped ready-hand rule). Then bulk dispositions.
python3 scripts/review-q2-queue.py \
  "$RIICHI_DATA_DIR/reviews/replay.ch34-shapes.2026-11/review-queue.jsonl" \
  --chapter ch34 --verdicts-out testdata/reports/q6-ch34/verdicts.json \
  > testdata/reports/q6-ch34/mechanical-review.json
$BIN --data-dir "$RIICHI_DATA_DIR" review --pack replay.ch34-shapes.2026-11 \
  --verdicts testdata/reports/q6-ch34/verdicts.json --json \
  > testdata/reports/q6-ch34/review-report.json

# 4. Sampled content sheet for the human sign-off. Every lesson under 120 bases
#    is included in full (nakabukure_ready 57, ryanmen_protorun 57,
#    protorun_plus_one 101).
python3 scripts/sample-review-sheet.py \
  "$RIICHI_DATA_DIR/reviews/replay.ch34-shapes.2026-11/review-queue.jsonl" \
  --sample 260 --per-lesson 30 --per-family 20 --include-all-below 120 \
  --seed q6-ch34-2026-11 --out-json testdata/reports/q6-ch34/review-sample.json \
  > testdata/reports/q6-ch34/review-sample.md

# 5. Persist the reviewed bases (variants are disabled by product decision;
#    the stage still runs its label-preservation check).
$BIN --data-dir "$RIICHI_DATA_DIR" transform \
  --pack-id replay.ch34-shapes.2026-11 --variants 1 \
  --seed q6-ch34-2026-11 --generated-at 2026-11-20T00:00:00Z \
  --workers 0 --progress --json \
  > testdata/reports/q6-ch34/variant-report-disabled.json

# 6. Assemble the reviewed bases only, drop duplicate actor hands, audit, and
#    publish all six hosted packs.
$BIN --data-dir "$RIICHI_DATA_DIR" pack assemble \
  --pack replay.ch34-shapes.2026-11 \
  --queue "$RIICHI_DATA_DIR/reviews/replay.ch34-shapes.2026-11/review-queue.jsonl" \
  --no-variants --unique-hands --min-bases-per-lesson 40 --max-scenarios 2000 \
  --licence CC-BY-4.0 --attribution "Ch.3/4 shape pack. <corpus attribution, see the pack>" \
  --generated-at 2026-11-20T00:00:00Z --commit q6-ch34-2026-11 --json \
  > testdata/reports/q6-ch34/assembly-report.json
$BIN --data-dir "$RIICHI_DATA_DIR" pack publish \
  --packs replay.ch34-shapes.2026-11,replay.ch9-seating-calls.2026-11,replay.ch5-values.2026-11,replay.ch7-riichi-dama.2026-11,replay.ch8-defense.2026-11,replay.ch8-defense-multi-threat.2026-11 \
  --updated-at 2026-11-20T00:00:00Z --json \
  > testdata/reports/q6-ch34/publish-report.json
node scripts/check-pack-hosting.mjs
node scripts/check-ch8-pack.mjs --allow-no-variants
node scripts/check-ch8-pack.mjs --pack replay.ch8-defense-multi-threat.2026-11 --allow-no-variants
node scripts/check-ch8-pack.mjs --chapter ch7 --allow-no-variants
node scripts/check-ch8-pack.mjs --chapter ch5 --allow-no-variants
node scripts/check-ch8-pack.mjs --chapter ch9 --allow-no-variants
node scripts/check-ch8-pack.mjs --chapter ch34 --allow-no-variants
node scripts/replay-coverage-report.mjs --json > testdata/reports/q6-ch34/coverage.json
```

The publish command lists all six packs on purpose: `--packs` replaces the
hosted set with exactly the ids given, so omitting an older pack would prune
its body. The five pre-existing bodies kept their content addresses
(`1e7f3266ea8f` is the only new hash).

## Review

- **Mechanical review** (`scripts/review-q2-queue.py --chapter ch34`): 868
  items, **868 accepted, 0 rejected**, no invalid reports, 0 duplicate
  exact/visible states, 0 dirty walks. The new `ch34` scope uses a **prefix
  list** (`ch3.`, `ch4.1`) because the pack spans three sections, names the six
  shipped lessons, and rejects out-of-scope sections/lessons, non-book or
  contested labels, report/lesson mismatches, illegal answers, duplicate
  exact/visible states and dirty walks. Its ready-hand rule is **lesson-scoped
  from each recogniser**:
  - `protorun_priority` (book ch3:205/230) and `protorun_plus_one` (ch3:574)
    require exactly 1-shanten, and `pair_count` (ch3:336/343) and
    `skipping_block` (ch3:713) exactly 2-shanten, so a ready hand is out of
    shape and rejected;
  - `nakabukure_ready` (ch3:690/702, ch4:694/725) has an explicit ready-hand
    cell (`shanten == 0`) beside its two 1-away cells, and `ryanmen_protorun`
    is a tenpai decision (three sets, a pair and a side-wait protorun), so both
    keep ready hands. This was checked against each recogniser rather than
    copied from ch. 5.
- **Bulk dispositions** (`review --verdicts`): 868 accepted, 0 rejected,
  0 pending, 868 valid reports.
- **Sampled content review:** 351 rows
  ([`review-sample.md`](../testdata/reports/q6-ch34/review-sample.md),
  [`review-sample.json`](../testdata/reports/q6-ch34/review-sample.json)) —
  per-lesson guarantees (30 each), per-family guarantees (20 each) and **all
  bases of the three lessons under 120**: 57 `nakabukure_ready`,
  57 `ryanmen_protorun` and 101 `protorun_plus_one`, plus 53
  `protorun_priority`, 42 `skipping_block` and 41 `pair_count` rows. The user
  sign-off is recorded below when received.
